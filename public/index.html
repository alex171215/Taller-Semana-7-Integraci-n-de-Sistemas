Plataforma de Gobernanza y Validación Contractual

Demostración en vivo de validación estricta en tiempo de ejecución con ajv mediante JsonSchemaValidationPipe, versionamiento compatible hacia atrás (v1 ➔ v2) y detección algorítmica de Breaking Changes (v2 ➔ v3).

Status: Production Ready
Paso 2 · Esquema v1

producto.schema.json

Contrato inicial estricto. Requiere nombre y precio. Prohíbe propiedades extras.

{
  "$schema": "2020-12/schema",
  "title": "Producto",
  "type": "object",
  "required": ["nombre", "precio"],
  "properties": {
    "nombre": { "minLength": 1, "maxLength": 120 },
    "precio": { "type": "number", "minimum": 0 }
  },
  "additionalProperties": false
}
Paso 5 · Esquema v2 (Compatible)

producto.schema.v2.json

Agrega categoria como campo opcional con enum. Respeta Backward Compatibility.

{
  "$schema": "2020-12/schema",
  "title": "Producto",
  "type": "object",
  "required": ["nombre", "precio"],
  "properties": {
    "nombre": { "minLength": 1, "maxLength": 120 },
    "precio": { "type": "number", "minimum": 0 },
    "categoria": { "enum": ["electronica", "oficina", "hogar"] }
  },
  "additionalProperties": false
}
Paso 6 · Esquema v3 (Breaking)

producto.schema.v3-breaking.json

Hace categoria requerida. Rompe clientes existentes que envían payloads en formato v1.

{
  "$schema": "2020-12/schema",
  "title": "Producto",
  "type": "object",
  "required": ["nombre", "precio", "categoria"],
  "properties": {
    "nombre": { "minLength": 1, "maxLength": 120 },
    "precio": { "type": "number", "minimum": 0 },
    "categoria": { "enum": ["electronica", "oficina", "hogar"] }
  },
  "additionalProperties": false
}
